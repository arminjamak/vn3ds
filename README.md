# vn3ds: Ren'Py visual novels on the Nintendo 3DS, in stereoscopic 3D

Ren'Py itself can't run on a 3DS: it needs a Python interpreter, pygame_sdl2
and OpenGL ES 2, none of which exist in usable form there, and it would not fit
in 256 MB of shared RAM. vn3ds doesn't port Ren'Py. It replaces it:

1. **`vnpack`** (Python, runs on your computer) parses a game's `.rpy`
   scripts, compiles the parts most visual novels use to a small bytecode,
   downscales every image to the 3DS's 400×240 top screen, pre-tiles it in
   the GPU's native texture layout and converts the audio to Ogg Vorbis.
2. **`vn3ds`** (C, citro2d) is a native 3DS visual-novel engine that runs
   that bytecode.

Because vn3ds owns the renderer, stereoscopic 3D is built in. A visual novel
is already a stack of flat layers, and each one is drawn once per eye with a
horizontal offset proportional to its depth, scaled by the 3D slider:

| layer | default depth | looks like |
|---|---|---|
| backgrounds, `scene` images, CGs | +1.0 (CGs +0.45) | sunk into the screen |
| character sprites | 0 to -0.2 (later-shown ones slightly nearer) | at the screen surface |
| textbox, name box | -0.35 | floating in front |
| menu choices, notifications | -0.5 | nearest |

The result is a pop-up-book effect. The art is still flat, so a sprite reads as
a cardboard cut-out rather than a 3D model.

```
RenPy/
  tools/vnpack/     converter + packager (Python 3, Pillow, numpy)
  engine/           3DS engine (C)  - Makefile for devkitARM, Makefile.host for desktop
  engine/host/      desktop test build: software renderer that writes PNGs
  examples/demo/    small demo game (art generated by examples/make_demo_assets.py)
  examples/syntax_test/  converter regression script

```

## Quick start

### 1. Port a game (on your computer): one command

Without installing anything (the standalone command, with Python and ffmpeg
inside; see [tools/cli-release/README.md](tools/cli-release/README.md)):

- **macOS**, in Terminal: type `curl -fsSL https://arminjamak.github.io/vn3ds/install.sh | sh -s -- `,
  drag the game into the window and press Enter.
- **Windows**, in PowerShell: type
  `& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((iwr -useb https://arminjamak.github.io/vn3ds/install.ps1).RawContentStream.ToArray()))) `,
  drag the game into the window and press Enter.

From this repository: Python 3.9+, `pip install pillow numpy scipy`, and
`ffmpeg` (only needed when a game's audio isn't already Ogg Vorbis).

```bash
tools/vn3ds-port path/to/Game
```

With no destination given, `vn3ds-port` finds one and prints each step: the
3DS's SD card if it is plugged into this computer (best quality; the game and
`vn3ds.3dsx` are copied, the engine only when it is missing or different),
otherwise the 3DS on the Wi-Fi (compact quality). Over Wi-Fi it first sends
vn3ds itself through the Homebrew Launcher's netloader when vn3ds isn't open
yet, then the game, in one run; it waits for the 3DS and retries dropped
connections until everything has arrived. `--sd /Volumes/3DS` or
`--3ds 192.168.1.23` choose the destination yourself, `--no-detect` only
builds the game folder.

`vn3ds-port` accepts a game in any of the shapes Ren'Py games ship in, and
it does the rest:

- **Inputs:** a Ren'Py project folder, a PC/Linux/Mac build, an Android
  `.apk`, a downloaded `.zip`, or loose `.rpa` archives. Pass several inputs
  when a game is split, e.g. an Android build plus its separate
  `archive.rpa`.
- **Containers:** archives are read in place where possible and unpacked
  only as far as needed.
- **Compiled-only games** (`.rpyc` without `.rpy`) are decompiled
  automatically with the bundled [unrpyc](https://github.com/CensoredUsername/unrpyc)
  (MIT licence, in `tools/third_party/unrpyc`).
- **Output:** everything is converted, a `port-report.txt` lists what was
  skipped or approximated, and with `--sd` the game and `vn3ds.3dsx` are
  copied onto the SD card (or an emulator's `sdmc` folder).

Useful options: `--rgb565` (textures about 60% smaller, slight banding;
recommended for very large games), `--jpeg 80` (opaque images as JPEG, about
a fifth of the RGB565 size; the default for Wi-Fi), `--no-audio`, `--fit`,
`-o build`. The Wi-Fi preset (`--quality wifi`) also uses ffmpeg's trellis
JPEG encoder (`--jpeg-encoder ffmpeg --jpeg-qscale 5.5`), stores CG variants
as patches over the picture before them (`--cg-patches`), JPEG movie posters
(`--jpeg-posters`), and H.264 at 100 kbps / 20 fps; `--no-cg-patches` and
`--no-jpeg-posters` turn those two off.

Tested with Eternum 0.9 (431 labels, 12,000+ images, ported from its
Android build in about 5 minutes), Ren'Py's own *The Question*, the Ren'Py
*Tutorial*, and the bundled demo game *Snapshot*.

Only port games you have the rights to.

### Wireless: port and send to the 3DS in one command

vn3ds listens for games over Wi-Fi the whole time it is open, even while
you play. With the 3DS on the same Wi-Fi as your computer:

```bash
tools/vn3ds-port path/to/Game --3ds 192.168.1.23
```

This ports the game and streams it straight onto the SD card. Nothing
stops for it: a small download icon turns in the top corner, and the home
screen shows the arriving game as a card with a progress bar and the time
left. You can open and play any other game meanwhile; the arriving one opens
once it is complete. An update to the game you are playing is kept aside and
applied the next time you open it. The IP to use is shown at the bottom of
the home screen and on the **Receive over Wi-Fi** screen (press **Y**).

**Installing or updating vn3ds itself, also over Wi-Fi:**

```bash
tools/vn3ds-port --install --3ds 192.168.1.23
```

- **If vn3ds is already on the receive screen**, this updates it in place;
  restart vn3ds afterwards.
- **If it isn't installed yet**, open the Homebrew Launcher and press **Y**
  (netloader). vn3ds-port sends the engine the way devkitPro's `3dslink`
  does (built in, nothing to install), vn3ds starts, opens its receiver on
  its own and saves itself to `sdmc:/3ds/vn3ds.3dsx`.
- Whenever a game is sent, vn3ds is sent with it (only if the 3DS's copy is
  missing or different), so `--install` is only needed to send vn3ds alone;
  `--no-engine` leaves it out.

**Using the ftpd homebrew app instead:** `--ftp 192.168.1.23:5000` uploads
the engine (with `--install`) and the game into `sdmc:/3ds/`.

The receiver only writes inside `sdmc:/3ds/vn3ds/games/` and to the engine
file itself; any other path is refused. Expect roughly 0.5–1 MB/s over the
3DS's Wi-Fi: a small game takes seconds, a 1 GB game like Eternum about
20–30 minutes.

### 2. Build the 3DS app

Install [devkitPro](https://devkitpro.org/wiki/Getting_Started) with the 3DS
packages, then:

```bash
sudo dkp-pacman -S 3ds-dev 3ds-zlib 3ds-libogg 3ds-libvorbisidec
```

```bash
cd engine && make
```

This produces `engine/vn3ds.3dsx`.

### 3. Copy to the SD card

```
sdmc:/3ds/vn3ds.3dsx
sdmc:/3ds/vn3ds/games/<game-id>/        <- the folder vnpack made
sdmc:/3ds/dspfirm.cdc                   <- needed for sound (dump it with DSP1)
```

Start vn3ds from the Homebrew Launcher. With one game installed it opens
straight to that game's title screen; with several you get a list.

## Controls

| | |
|---|---|
| A / touch | advance, choose |
| D-pad / circle pad | move through choices and menus |
| R (hold) | skip |
| L | auto-forward on/off |
| Y or D-pad up | history (backlog) |
| X | save |
| START | settings (text speed, auto-forward, **3D depth**, textbox opacity, volume) |
| SELECT | hide the textbox to look at the picture |

The bottom screen shows recent dialogue and Log / Auto / Skip / Save / Load /
Menu buttons, and the choices whenever a menu is open. There are 30 save slots
per game; saves live in `sdmc:/3ds/vn3ds/saves/<game-id>/`.

## Tuning the 3D

Put a `vn3ds.json` in the game's `game/` folder, or pass `--config file.json`:

```json
{
    "depth": { "bg": 1.0, "cg": 0.5, "eileen": -0.1, "eileen happy": -0.15 },
    "depth_bg": 1.0,
    "depth_sprite": 0.0,
    "depth_ui": -0.35,
    "max_shift": 6.0,
    "fit": false
}
```

- `depth` sets depth per image tag or per full image name (positive = behind the screen).
- `max_shift` is the per-eye pixel shift at depth 1.0 with the slider all the
  way up. The in-game "3D depth" setting multiplies it by 0 to 2.
- Ren'Py's own `zpos` transform property also works: positive `zpos` comes
  towards you.
- `fit: true` always letterboxes. By default a 16:9 game is scaled to fill the
  5:3 screen and loses about 13 px on each side; 4:3 games are pillarboxed.

Full-width images that sit behind the screen are enlarged slightly so their
stereo offset never shows a black strip at the edge.

## What converts

**Supported**

- `label` (including local `.labels`), `jump`, `call`, `return`, fall-through between labels
- dialogue: `"text"`, `e "text"`, `"Name" "text"`, `e happy "text"` (say attributes), `extend`,
  `centered`, `narrator`, NVL characters (shown in the textbox), `[variable]` interpolation
  with `!u !l !c`, `[[`/`{{` escapes, `{p}`, `{nw}`
- `Character(...)`: name, `color`/`who_color`, `what_color`, `image`, `kind`,
  `what_prefix`/`what_suffix`, `dynamic`, `DynamicCharacter`
- `scene`, `show`, `hide` with `at`, `as`, `behind`, `zorder`, `with`, `expression "file.png"`,
  and attribute resolution the way Ren'Py does it (`show eileen sad` keeps other attributes,
  `-attr` removes one)
- `image` statements: files, colours, `Solid`, `Composite`/`LiveComposite`, `Transform`
  (zoom, flip, alpha, size), `im.Flip`/`Scale`/`FactorScale`/`Crop`/`Grayscale`/`Sepia`/`Alpha`;
  automatic images from `game/images/`
- positions `left right center truecenter top topleft topright offscreenleft offscreenright reset`
- ATL in `transform` blocks and `show ...:` blocks: `xpos ypos xanchor yanchor xalign yalign
  align pos anchor xoffset yoffset offset xcenter ycenter xycenter zoom xzoom yzoom alpha rotate
  zpos`, `linear`/`ease`/`easein`/`easeout` (and `ease_*` variants), `pause`, `block`,
  `repeat [n]`, `parallel`, `on show/replace`, transform parameters
- transitions: `dissolve`, `fade`, `Dissolve()`, `Fade()` with colour, `move`, `ease`,
  `movein*`/`moveout*`/`easein*`/`easeout*`, `vpunch`, `hpunch`, `MoveTransition`,
  `with None`; wipes, slides, pushes, irises, blinds, pixellate and zooms play as dissolves
- `menu` with caption, conditions (`"choice" if x:`), menu labels, nested menus
- `if`/`elif`/`else`, `while`, `pass`
- `$` lines, `python:` blocks and `define`/`default` with assignments, `+=` etc., arithmetic,
  comparisons, `and`/`or`/`not`, conditional expressions, f-strings, `renpy.random.randint`,
  `len`, `str`, `int`, `min`, `max`, `round`, and the calls `renpy.pause`, `renpy.jump`,
  `renpy.call`, `renpy.music.play/stop/queue`, `renpy.sound.*`, `renpy.show/hide/scene`,
  `renpy.with_statement`, `renpy.say`
- `play`/`queue`/`stop` for `music`, `sound`, `audio` and `voice`, with `fadein`/`fadeout`,
  `loop`/`noloop`, `if_changed`, `audio.*` names and files under `game/audio/`
- `pause`, `window show/hide/auto`, `config.name`, `config.version`, `gui.init(w, h)`,
  `gui/main_menu.png` as the title-screen picture
- `Movie(play=...)` images (animated scenes): re-encoded to H.264 (needs `ffmpeg` with
  libx264) at the clip's own frame rate up to 30 fps, played by the New 3DS's hardware
  decoder; an Old 3DS shows the clip's first frame. `--video-kbps` (default 900; 100
  for a Wi-Fi edition), `--video-fps` (cap), `--video-seconds`, `--no-video`, and
  `--video-codec cvid` for the older tiled format (12 fps, any 3DS). They play at the depth
  of the image, flat but with the camera parallax.
- `call screen` navigation screens made of buttons (maps, phone menus) become a menu, with the
  screen's background picture shown behind it
- string methods `upper lower title strip capitalize`, indexing and slicing, and
  `renpy.input` (returns its default name)

**Not supported** (vnpack warns and skips them)

- screen language: custom screens, `show screen`, custom main/game menus (`call screen` only
  as above)
- Python beyond the subset above: functions, classes, lists, dicts, objects
- `layeredimage`, animated images other than `Movie` (the first frame is shown), live text
- ATL `function`, `choice` (the first choice is used), `contains`, `time`, events other than show
- `nvl` page layout, text styles inside a line (`{b}`, `{color}`, `{size}` are dropped), rollback
- `persistent.*` values work as ordinary variables saved with each save, not across playthroughs

## Testing without a 3DS

`engine/Makefile.host` builds the same engine against a software renderer. It
plays a packed game, pressing A through dialogue and taking menu choices from
`--choices`, and writes one PNG per line: both eyes, a red/cyan anaglyph and
the bottom screen.

```bash
make -C engine -f Makefile.host
engine/build-host/vn3ds-host build/snapshot --out frames --choices 0,1 --test-save
```

The demo game:

```bash
python3 examples/make_demo_assets.py
tools/vnpack.sh examples/demo -o build
```

Inspect a compiled script with `python3 -m vnpack.disasm build/<id>/game.bin` (from `tools/`).

## Limits worth knowing

- Textures are capped at 1024×1024 and cached in about 20 MB of linear RAM.
  A typical scene (background + two sprites) uses about 1 MB.
- Text uses the console's system font. It covers Latin, Japanese and the
  console region's characters; custom fonts in the game are ignored.
- Scripts are bounded at 2 million instructions between interactions, so an
  accidental infinite `while` loop shows an error instead of hanging.

## Engine features beyond plain Ren'Py (all optional, via `game/vn3ds.json`)

A game ports fine without any of these; they're hints that make it better on
the 3DS. Snapshot (`examples/demo`) uses all of them.

- **`depth`**: per-tag or per-image 3D depth (see "Tuning the 3D").
- **`layers`**: draw an image as several depth planes, each with its own 3D
  offset and an optional motion (`sway`, `pulse`, `breathe`, `fall`,
  `rise`, or `stars`: a procedural, twinkling starfield that comes out a
  little different every time the picture is shown). Snapshot's scenes are drawn this way by `examples/scenes3d.py`;
  the flat image in `images/` stays for Ren'Py on a PC.
- **`camera`**: a slow camera drift and zoom "breath" with true parallax
  (`{"drift": 4.5, "period": 19, "zoom": 0.015}`).
- **`voices`**: speech-like machine voices, a bank of synthetic syllables
  played as text appears, pitched per character variable, with the music
  ducked underneath (`{"bank": [...], "pitch": {"a": 1.0}, "volume": 0.32,
  "duck": 0.8}`).
- **`music`**: each track's tempo grid, so the music plays as one continuous
  score: when the script changes music (`play music`, or `stop music
  fadeout` followed by a `play music`), the current track finishes its loop
  or its phrase and the new one comes in on the downbeat, at most 8 s later;
  without a grid it crossfades on the beat. `{"audio/cafe.ogg": {"bpm": 82,
  "beats_per_bar": 4, "phrase_bars": 4, "bars": 16}}` (`bars` = the loop's
  length). Snapshot's is written by `examples/music/meta.py` from the score.
- **Ren'Py's `camera` statement** (standard Ren'Py) moves the whole scene with
  ATL: `xoffset`, `yoffset`, `zoom`, `rotate` and `zpos`, plus `xrotate` and
  `yrotate`, which on the 3DS tilt and orbit around the screen plane so a
  scene's layers slide past each other. Snapshot's `camera.rpy` builds a
  handheld-documentary grammar from it (establishing loops, mediums,
  close-ups, punch-ins).
- **Minigames**: `$ score = vn3ds_minigame("snake")` plays one of vn3ds's
  native minigames and returns its 0-100 score; the title screen gets a
  Minigames menu with best scores. Define `vn3ds_minigame()` in your game
  for PC (Snapshot's `minigames.rpy` shows a stand-in). Music and sounds come
  from `game/audio/minigame/`.
- **`config.speaking_attribute`** (standard Ren'Py) is honoured: while a
  character speaks, the engine flaps between their image and the image with
  that attribute, e.g. `aron tired` and `aron tired talk`.
